# 核心概念与术语

通读这一页，管理面板和设置页里的所有名词就都能对上号了。

## 方案（Profile）

一条**上游接入配置**，是整个系统最基本的单元。一个方案包含：

- **协议**：Anthropic（`/v1/messages`，给 Claude Code 用）或 OpenAI Responses（`/v1/responses`，给 Codex 用），两套协议完全隔离、各自管理
- **上游地址**：真正的 AI 服务商接入点
- **URL 后缀**：每个方案有一个后缀，例如方案后缀为 `pp` 时，成员可以用 `https://服务器地址/pp/v1` 直连这个方案
- **模型别名**：对外暴露的模型名 → 实际上游模型的映射
- **配额与计费**：额度池、峰谷倍率等

在设置页里新建和管理，按协议分列。

## 协议

- **Anthropic**：Claude Code 使用的协议，入口 `服务器地址/v1`
- **OpenAI Responses**：Codex 使用的协议，入口 `服务器地址/v1/responses`

面板顶栏的「全部 / Anthropic / OpenAI」三段开关就是在切换展示哪套协议的方案与数据。

## 组头与基础组

- **基础组**：设置页侧栏里的「默认方案组 / OpenAI 方案组」，是一个**有序名单**。排在第一位的是**组头**，请求默认打到组头方案；组头限流或熔断时自动 failover 到下一位，组头恢复后自动回切
- **方案组调度**：可以在不同时间用不同的有序名单接管基础组（见[方案组调度](schedule.md)），被调度规则选中的组，其第一位成员就是当时的组头

「限制直连」勾选后，基础组与全部调度组内的成员方案都不允许通过 `/后缀` URL 直连，只能走组调度。

## 虚拟 Key（`jx-`）

团队成员的身份凭证，形如 `jx-xxxx`。成员拿虚拟 Key 接入，系统据此识别「这是谁」；真实上游 Key 只存在服务端配置里，永不暴露给成员。在设置页的「用户管理」里创建，可设失效时间、可禁用。

## 额度池

**同一上游套餐的方案**放进同一个池，共享同一份额度判定。例如两个方案背后是同一个 Claude 订阅，就把它们设为同一个额度池——两个方案合计消耗这个池的配额。池在设置页按方案维护，侧栏「额度池」入口显示池列表。

## 配额与配额优先级

**配额存在「额度池」上**——池是配额的唯一载体（方案级每日限额是旧版设计，已迁入池）。判定规则：

```text
限额 = 用户在该池的个人配额（设了就用它）否则池级每日配额
     + 当日临时加量
判定 = 当日计权用量（已减当日重置基线）< 限额
```

- 限额 ≤0（个人与池都没设）→ **不限制**
- 同池多方案共享同一份额度；一个用户可同时属于多个池，各池独立计账
- 超限的请求收到 429，错误信息带 `quota_exceeded` 标记、剩余额度结构与距北京时间零点的重试秒数（每日零点重置）

完整判定流程与公式见[配额与计费机制](mechanism-quota.md)。

## 配额倍率（峰谷倍率）

扣配额时的加权系数，只影响**配额判定**，报表永远显示真实 Token：

- **峰谷两档**：方案可设高峰时段（北京时间，每日重复），峰时用「峰倍率」，平时用「谷倍率」；**不配高峰时段 = 全天按谷倍率**
- **按模型倍率**：为个别模型（按真实上游模型名）设独立倍率，模型级优先，未配置回落方案默认
- **`weighted_tokens`**：计费输入与输出 × 倍率 = 计入配额的加权用量
- **锚定约定**：×1.0 = 高峰时段一个 token 按方案默认价，让名义每日限额有意义
- **缓存**：缓存写入与 Anthropic 缓存读**均不计入配额基数**；Responses/OpenAI 的缓存命中默认剥离不计（`cacheReadQuotaRate` 可选择按比例计回）

公式、数字示例与全部细节见[配额与计费机制](mechanism-quota.md#weighted_tokens-配额货币的完整公式)。

## 高峰时段

每个方案可配置每日重复的时间段（北京时间），命中时段触发两件事：峰倍率生效；若配置了「高峰期模型别名覆盖」，对外模型别名也会切换到高峰版。

## 临时额度 / 签到奖励

- **临时额度**：管理员在用户管理里给成员临时加量，**当日生效、次日失效**；也可用于重置某人今日用量、撤销今日手工操作（三个操作的精确语义见[这里](users.md#临时额度到底改了什么)）
- **签到奖励**：成员每日在「我的用量」页签到，随机获得一笔 token 额度，有连续天数记录
- **加量申请**：成员提交申请（选额度池、写理由），管理员在设置页侧栏「加量申请」里审批，可通过、拒绝并附备注

## 自动配额调整

开启后，系统按近 N 天配额命中率**自动上调**额度池配额（可配评估周期、命中率阈值、冷却时间），调整记入审计日志，与临时加量互不干扰。

> ⚠️ 三个容易踩坑的约束：只评估**默认方案所属池**；只评估**设了个人配额**的用户；命中率分母是**周期总天数**（不是有用量天数）。完整算法与示例见[配额与计费机制](mechanism-quota.md#自动配额调整-auto完整算法)。

## 熔断与半开探测

上游**连续失败达到阈值**（默认 5 次）后，该方案被**熔断**（暂时退出 failover 候选），流量自动走下一位。冷却期（默认 30 秒）结束后进入**半开探测**：放探测请求试探上游，成功则恢复；失败则冷却翻倍重试（指数退避 ×2，封顶 8 倍 / 最长 5 分钟）。全程无需手工重置，设置页和方案中心能看到熔断状态与距下次探测的秒数。状态机细节见[代理与调度机制](mechanism-proxy.md#熔断器状态机)。

## 粘性会话

同一个会话的请求**粘**在同一个方案上，避免会话中途切换方案导致上游缓存冷启动（多花钱）。会话信号识别优先级：`session_id` 请求头 → `prompt_cache_key` → 首轮内容摘要。粘性绑定只指向组头位置，组头恢复后自然回切。

## 客户端

调用方的程序识别，与协议正交：`claude-cli`（Claude Code）、`codex_cli_rs`（Codex）、`zcode` 等。面板「客户端用量」工作区与个人用量页的客户端表都按此统计。

## 会话

一次连续对话单元，是产出质量分析和缓存率分析的基本单位。会话在面板和个人页里都会显示可读标题（根据首轮对话内容生成）、Token、缓存率、净产出。

## 产出质量指标

基于会话中的工具调用事件统计（只记行数/路径/命令分类，**不存任何代码内容**）：

| 指标 | 含义 |
|---|---|
| 净产出 | 新增 + 修改的有效行数 |
| 失败率 | 工具调用失败占比 |
| 重写率 | 对同一文件反复重写的比例 |
| 验证密度 | 测试/验证类操作相对产出的密度 |
| Token 效率 | 单位 Token 产出的有效行数 |

## 等值成本

把 Token 按可编辑的**参考牌价**折算成美元，用于估算「这些用量如果按牌价买要花多少」，支持峰谷分时定价。只是参考值，与真实账单无关。

## 审计日志

设置页侧栏「操作日志」，分四类：**admin**（管理员操作）、**system**（系统自动行为，如自动配额调整）、**checkin**（签到）、**request**（加量申请）。保留最近 3000 条。

## 北京时间口径

所有对用户展示的时间（今日用量、零点重置、高峰时段、调度规则）一律按 **UTC+8**；数据存储用 UTC。
