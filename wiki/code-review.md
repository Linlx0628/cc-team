# 代码评审

系统把登记过的仓库拉到服务器本地,用 [open-code-review](https://open-codereview.ai)(阿里开源的 OCR CLI)做**行级代码评审**,结果进管理面板「代码评审」工作区,并可推送通知。评审消耗走本网关的**评审专用 Key** —— 也就是计入用量与配额,和日常使用同一套账。

> ⚠️ **这是本系统唯一会执行外部命令的功能**(`git` 与 `ocr`),因此**默认关闭**,只有管理员能配置,成员无法提交任意仓库地址。

## 前置依赖(装在哪台机器上)

| 依赖 | 要求 | 安装 |
|---|---|---|
| `git` | ≥ 2.41 | `apt install git` / `apk add git` |
| `@alibaba-group/open-code-review`(`ocr`) | 能跑 `ocr version` | `npm i -g @alibaba-group/open-code-review` |
| `openssh-client` | 仅 SSH 拉私有仓库时需要 | `apk add openssh-client` |

网关**不会自动安装** OCR:未检测到时会显示「未安装」与安装命令,由管理员自行处理。设置页的「代码评审」卡片顶部会显示探测结果(OCR 版本与 git 版本)。

## 三步启用(不需要填任何 API 信息)

系统本身就是 AI API 网关,评审只是「另一个经网关的调用方」—— 所以只需要选方案,不用配 Key/端点/协议:

1. **选方案**:设置页 → 左栏「代码评审」→「评审用哪个方案」下拉选一个已有方案(端点与协议由系统按该方案自动推导)
2. **一键创建评审账号**:点「创建评审账号」即可。系统生成 `jx-review-…` 专用账号并设为超级用户,运行期向所选方案**借用已有的真实 Key**(不需要你填);用量记在「代码评审」名下,便于对账
3. **加仓库白名单并打开总开关**:「＋添加仓库」填名称、来源(`remote` 填 `https://`/`ssh://`/`git@` 地址,`local` 填服务器上已有仓库的绝对路径)、分支;可选凭据/定时/在线触发

引擎参数(并发、超时、token 预算等)收在「高级参数」折叠区,默认值一般不用动;端点强制回环(`http://127.0.0.1:<端口>/v1`),防止把评审流量指向外部。

## 四种触发方式

| 方式 | 怎么用 | 说明 |
|---|---|---|
| 手动 | 管理面板 → 代码评审 → 选仓库 → 开始评审 | 同仓库已有任务在跑时返回同一个 runId(去重) |
| 定时 | 设置页给仓库配「固定间隔 / 每天定时」 | 每 60 秒扫描一次;按**北京时间**判定;到点且该仓库无进行中任务才入队 |
| CI | `curl -X POST /api/code-review/trigger` + 虚拟 Key | 需要该 Key 在「允许 API/MCP 触发的 Key」白名单里,且仓库开了「允许在线触发」 |
| MCP | agent 调用 `code_review_trigger` / `code_review_list` | 同上白名单;未授权的 Key 在工具列表里**看不到**这两个工具 |

## 来源与拉取行为

| 来源 | 怎么填 | 评审前做什么 | 凭据 |
|---|---|---|---|
| **remote** | 线上仓库地址(`https://` / `ssh://` / `git@`) | 每次评审前 `git fetch` 该地址并 reset 到目标分支最新 | 公开仓库选「无凭据」;私有仓库填 HTTPS Token 或 SSH 私钥路径 |
| **local** | 服务器上仓库的**绝对路径**(如 `/Users/xxx/Project/my-app`) | 首次评审时从该路径 clone 一份到工作区;之后每次评审前从该路径 `fetch` 最新提交 | 不需要凭据(本机路径) |

- **填入只是登记白名单,不会立即拉取** —— 第一次触发评审(手动/定时/CI)时才 clone,之后每次评审前自动同步到目标分支最新
- ⚠️ 评审基于**已提交**的内容:本地仓库里未 commit 的工作区改动不会被评审 —— 想评什么就先 commit
- 本地路径要求:是一个 git 仓库(有 `.git`)且至少有一个提交;克隆进工作区后你的原仓库不会被改动(评审在独立副本上进行)

## 评审范围(增量口径)

```text
首次评审:  --commit HEAD                       只评最新一个提交(避免大仓库首评烧穿套餐)
之后每次:  --from <上次评审到的提交> --to <HEAD>  等价 git merge-base(from,to)..to 的增量
历史被改写(上次的提交已不是 HEAD 祖先):自动回退为单提交评审,并在运行详情标注
游标推进:  success / completed_with_warnings / completed_with_errors / skipped 都推进;
          failed / timeout / canceled 不推进 —— 下次仍从上次成功处开始
```

游标存在数据库(`code_review_repo_state.last_commit`),不写 config。

## 结果怎么看

工作区列表每行:`时间 | 仓库 | 触发方式 | 范围(短 SHA) | 状态 | 文件数 | 意见数 | token | 耗时`。点「详情」按文件分组展开每条意见:定位行号、问题描述、原代码、建议改法、OCR 的推理过程。

状态含义:`完成`(可能零意见)、`完成(有警告)`、`完成(有错误)`、`失败`、`超时`、`已取消`、`已跳过`(超出当日预算)。

**token 归因有两个口径**,详情页同时给出:OCR 自报的 token(`summary`),以及**网关侧实证** —— 评审 Key 在 `users` 表的请求数与 token 在本次运行前后的差值。两者可能有偏差(OCR 一次评审会发多次 LLM 请求,无法一一对应到单次运行),以网关侧为准来对账。

## ⚠️ 注意与边界

- **代码片段会入库**:评审意见里的原代码与建议代码默认写入 SQLite(`storeComments: true`)。这是本系统第一次把源码内容落库;可在设置里关掉(只存统计),也可用「清空评审数据」整体清除。
- **磁盘占用**:每个仓库一份完整检出 + 评审产物(`code-review-workspaces/`,已在 `.gitignore` 里)。`perRepoDiskLimitMB`(默认 2048MB)是**每仓库**上限,超限拒绝入队并通知;可在设置页查看占用与清理。
- **工作区不是只读仓库**:系统会 `git reset --hard FETCH_HEAD` 强制同步到目标分支,**不要**把手工改动放在这里。
- **凭据**:HTTPS Token / 私钥路径存在 `config.json`(与方案真实 Key 同一信任级别),只经子进程环境变量传给 git,**不进命令行参数、不进日志**;界面与接口只回掩码。
- **子进程环境是白名单重建的**:`ANTHROPIC_API_KEY` / `OPENAI_API_KEY` / `*_TOKEN` 等一律不传给 OCR —— 否则它可能绕开指定的 provider 直连上游,导致计费与审计双失守。
- **被拒绝的用法**:非 `https/ssh/git@` 的仓库地址(含 `file://`、`ext::`)、以 `-` 开头的地址或分支、非十六进制的提交号、把端点配成非回环地址 —— 都会被拒绝。
- 定时任务按 **间隔** 或 **每天某时刻 + 星期** 判定;同一仓库同时只会有一个任务(串行),避免 git 工作树被并发写坏。
