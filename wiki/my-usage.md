# 我的用量页

成员侧主页，地址 `/usage/<你的虚拟Key>`（也可在 `/my-usage` 输入 Key 跳转）。**无需登录后台**，持有 Key 即可查看自己的用量。左侧栏八个分区 + 底部「**文档**」链接（打开使用手册的**成员版**：只显示成员用得到的章节，看不到管理员指南；管理员直接访问 `/wiki/` 看到的才是完整手册）+ 右下角吉祥物挂件。

## 概览

- **协议切换**（全部 / Anthropic / OpenAI）+ **方案下拉**：切换查看范围。这个下拉只决定「看哪个方案的数据」，不改变请求实际走哪个方案
- **请求方案列表**（仅启用点数预算且管理员允许时显示，位于概览）：按 **Anthropic（Claude Code）** 与 **OpenAI（Responses）** 两组分别展示表格。列固定为：方案名、高峰期、四列「最强级/高级/中级/普通 + `jx-fable`/`jx-opus`/`jx-sonnet`/`jx-haiku` + 当前系数」、限额情况、操作。每组第一行是「**默认自动**」——不是写死的组头，而是按当前方案组调度配置算出的生效组与组内优先方案；这一行只显示调度组/当前优先的一行摘要，不展开别名详情。其余方案行直接展示四个别名当前实际映射到的真实模型与当前点数倍率。可用方案可点「选择」；不可用方案（限流、熔断、额度耗尽、未分配 Key）整行红色、按钮禁用，并在「限额情况」写出原因。当前处于方案配置的高峰时段时，「高峰期」列显示标签。选中方案是**手动首选**：会覆盖「默认自动」的调度组，即使该方案当前不在自动调度组，选中后请求也只走它。**选中后不会自动切换到其他方案**：该方案被限流、熔断、额度耗尽或未分配 Key 时，请求会直接失败并返回原因；概览里的该行会保留红色并显示限额/恢复信息，方便你改选或等待恢复。改选只影响新请求，保存后会清掉该协议的粘性绑定。

> 如果请求的模型/别名没有在当前方案启用，返回 403 并明确提示「模型未在方案启用，请切换到该方案已启用的模型」，不会把它误报成“方案不可用/已停止自动切换”。

列表的四列别名固定按 `jx-fable`（红色「最强级」）、`jx-opus`（橙色「高级」）、`jx-sonnet`（蓝色「中级」）、`jx-haiku`（绿色「普通」）排列，其他别名不占列。每个单元格显示**当前时段实际使用的真实模型**和**当前点数倍率**：高峰时段自动切换为该方案配置的高峰模型，不提前展示高峰模型名
- **本期点数卡**（仅启用点数预算时显示）：剩余点数、预算/已用、周期起止、进度条、日均消耗与预计耗尽日；1 点 = 10,000 计费计权 token。预算为 0 或已用满时整卡转为告警色。切换「请求方案」不会改变点数总额，只改变后续请求优先走哪个方案。点数卡下方「计费公式」可展开：1 点 = 10,000 计费计权 token；点数额 =（新鲜输入 + 输出）× 当前点数倍率 ÷ 10,000 × 平台调整系数（系数不展示，实际以请求记录的点数为准）；缓存写入不计，缓存读取默认不计（Responses 在方案开启缓存系数时按该系数折算，Anthropic 读取不计）
- **签到**：未启用点数预算时显示「签到条」，每日签到领随机 token；启用点数预算后改为在「本期点数」进度条末尾的「签到」按钮，每日领随机点数并直接加到本期预算（显示今日获得、连续天数）。两种奖励互不混用：token 奖励进额度池当日加量，点数奖励进本期点数预算
- **指标卡**：今日用量、今日请求、今日输入 / 输出、缓存写入、缓存命中
- **配额提示条**：临时加量、今日已重置、AUTO 自动调整、当前倍率等状态提示；点数模式下改为显示本期预算、周期结束时刻、已超出点数
- **各方案配额卡片区**：选「全部可用方案」时，每个可用方案一张卡——配额进度条（按紧张度着色）、配额来源、倍率与抵扣、（有调度时）下次切换时刻。点数模式下，池级日限额只作为「团队池护栏」显示；若池级也不限，这一区隐藏
- **使用日历**：GitHub 风格的年度热力图（往回 371 天，含今天）。**着色是相对自己的分位数**——活跃天的 25/50/75 分位切 5 档色阶，深色 = 超过你过去一年 75% 的活跃天；悬浮看当日明细，下方汇总活跃天数、最长连续、最高单日（「最长连续」统计的是有记录日期的连续段，无流量的日子不在序列里、不会打断计数）。日历数据**进页与切日期范围时全量拉取一次**，之后 30 秒轮询只刷新今日格（历史格子不会变），减少不必要的下载
- **产出画像**（仅自己可见）：净产出、失败率、缓存命中率建议、趋势

## 配额价目表 / 点数价目表

页面标题会按计费模式切换：启用点数预算的成员看到「**点数价目表**」，其余成员看到「**配额价目表**」。当前时段**每个别名**的倍率一览，**最便宜的排最前**；模型单独定价按真实上游模型名匹配，倍率锚定 ×1.0 = 高峰时段默认价。点数模式下这一列显示的是**点数倍率**（独立于额度池倍率，留空按 1.00），最右列把倍率换算成“约点数/百万”。倍率怎么算的见[配额与计费机制](mechanism-quota.md#点数倍率与计费系数)。花钱之前先看这页，选便宜又够用的模型。

## 用量分析

- **日期范围 + 快捷周期筛选**：默认选中「今日」与「本周」，点「重置」恢复默认档
- **今日 24 小时趋势图**：半小时粒度（48 桶，北京时间），跟随日期范围筛选
- **用量趋势**：双轴折线图
- **今日模型请求表**：请求数、实际 Token、倍率、计入配额四列**并排**展示——「实际 Token」= 输入+输出（不含缓存），「计入配额」= 额度池计权后的扣减值；点数模式下还有「点数」列，显示这次请求按独立点数价目扣了多少点（详见[配额与计费机制](mechanism-quota.md#weighted_tokens-配额货币的完整公式)）
- **客户端用量表**、**项目分布表**（文件数 / 净产出 / Token / 缓存率）

## 请求明细

「请求明细」是点数成员的**逐次扣点凭证**：每次成功的 API 请求一行，回答“我这次到底扣了多少点”。

- **一行一条请求**：时间（北京时间）、方案、实际模型、输入/输出/缓存读 token、点数倍率、扣点。不记录对话正文、系统提示或响应内容。
- **只记成功请求**：失败、被拒、被限流、额度不足的请求不扣点，也不入表；所以“明细合计”与“概览已用”能对上。
- **区间合计**：表格上方按当前查询区间显示合计点数与请求次数，数据来自点数用量日桶，不随翻页重复累加。
- **分页**：默认 30 条一页，用“加载更多”按请求 ID 向前翻页；不会因为新请求插入而出现重复或跳行。
- **保留期 90 天**：更早的逐请求记录会被自动清理；日/周/月点数汇总仍保留在 `point_usage`，不影响预算判定。
- **查询区间**：默认只看**当天**；要看历史，改起止日期后点“查询”。最多展示 90 天内的记录。

> 点数倍率是方案配置的当前时段倍率；用户/方案计费系数属于平台调整项，不在这里展示，最终以“扣点”列为准。

## 会话使用情况

自己的会话卡片：可读标题、客户端、Token、缓存率、净产出；支持日期范围与快捷周期筛选。

- 卡片标题来源：优先会话文件里的可读标题，其次项目名，都没有就写「无代码产出」——它只表示**没有可归属的代码项目**，不代表没有工具调用（工具/文件/净产出三格照实显示）
- 「会话数」卡片副标题给出碎片数与占比（碎片 = 轮数 ≤2），若自己名下出现过自动化（代码评审）会话，会另注「其中自动化 N 个」

## 团队排行榜

按排序维度（可切换）+ 时间窗（今日 / 7 天 / 30 天）的团队排行，前三名有领奖台样式。

- **样本不足**：缓存率 / 上下文健康度要求本期请求 ≥ 50 次、效率比要求净增 ≥ 50 行、代码质量要求编辑 ≥ 10 次才参与排名。不达标者数值照常显示并带橙色「样本不足」标，但排在所有达标者之后，也不进领奖台——防止只发几次请求就靠高命中率登顶
- **无人达标**：本期没人过门槛时（今日窗口常见），榜单上方会注明「按原始数值排序，仅供参考」
- **代码类维度只统计代码**：写 `.md` 等文档不算代码行数、不参与代码质量评分（详见[指标口径](metrics-reference.md)的「团队排行榜」一节）
- 领奖台只在前三名全部达标时出现；cohort 行会显示「本期 N 人活跃 · 其中 K 人达标」

## 代码评审

左栏「代码评审」分区：显示**你负责的仓库**（管理员在设置页把你的 Key 加进仓库的成员名单后出现），另加一类 —— **push 邮箱是你本人**的运行（评审通知按邮箱定向发给你时，哪怕你不是该仓库成员，对应记录也会出现在这里，详见[代码评审](code-review.md#评出问题后通知谁)）。

- **仓库卡片**：每个仓库一行 —— 名称、上次评审状态、默认分支、上次评审时间；连续失败会标红。若该仓库没开「允许在线触发」，会标注「仅可查看,未开外部触发」—— **能看到结果**与**能从外部触发**是两件事
- **评审记录**：时间倒序最多 20 条，每条含 时间 / 评审范围（来源标签 + 短 SHA，如 `增量 1a2b3c4d→5e6f7a8b`、`冷启动回溯 …`）/ 覆盖提交数 / 文件数 / 意见数 / token，以及一句**结论**（「选取 N 个文件,未发现问题」「自上次评审以来没有新提交」这类人话）；评出过意见的记录带 **已解决 / 未解决** 标签
- ⚠️ **「部分完成」要认得出来**：引擎撞到单次 token 预算时会**停止派发后面的文件**（已评出来的意见照常保留），这条记录的状态是「**部分完成**」（深橙色），文件数写成 `文件 10/39`（已评/选取）并带「覆盖不全,详见详情」——
  - 详情弹层里会写明「本次没有评完：选取 39 个文件，评了 10 个，29 个未评审（超出单次 token 预算）」，并列出未评文件；**0 条意见时不再是绿字**「本次没有提出意见」，而是橙字「已评审的 10 个文件没有提出意见 —— 这不等于『没有问题』,未评审的文件没有被检查过」
  - 这一版之前产生、状态写成「完成(有错误)」的老记录，也会被同样标出来（有原始报告时现算出覆盖率，没有时至少给 ⚠）
  - **撞顶后网关会先自动续评**（用同一个引擎会话只补没评到的部分，已评的复用不重复付费，默认最多 2 轮），所以留下「部分完成」说明续评也补不完；**残留的文件不会在下次评审里自动补**（游标照常推进），要补得找管理员调高「单次 token 预算」或「自动续评轮数」再用「按范围补评」重评那一段 —— 详见[单次预算撞顶:部分完成](code-review.md#单次预算撞顶部分完成)
- 点「**详情**」弹层查看该次运行的意见：带搜索与分页，每条给行号、问题描述，原代码 / 建议改法可折叠；头部还写着这次**为什么是这一段**（范围来源，如「这条分支首次评审:回溯最近 10 个提交」）、**本次覆盖的提交清单**（提交号 / 标题 / 作者 / 时间），以及「**评审标准 v…**」—— 这一版所有仓库共用同一份标准，两次评审意见数不同时先核它是不是同一版（口径不同不可直接比），另外若本次有意见因为「没写取证推理」被丢弃，这里也会写明丢弃条数；评出过意见的记录在弹层头部有「**标记已解决**」按钮（再点一次撤销）
- **只列「跑完了」的记录**：**失败 / 超时 / 已取消**这三种运行不出现在这里——它们是「压根没跑出评审结果」，多半出在网关、Key、网络这类**管理员该处理**的配置上，挂在成员列表里只会变成一行长期存在、问不出结果的红字。这些记录仍保留在[管理面板](dashboard-workspaces.md)的「代码评审」里，管理员排查完可以逐条删掉（见[维护与清空](code-review.md#维护与清空)）
- **「已跳过」照常列出**：它是**有意没跑**（超出当日 token 预算 / 自上次评审以来没有新提交），不是「没跑成」。点「详情」能看到具体原因，详情底部也会写明「本次已跳过，没有进行评审」——不会用绿字说成「本次没有提出意见」
- ⚠️ **仓库卡片上的状态仍包含失败**：记录列表里看不到失败，但卡片照实反映仓库健康（上次状态、连续失败次数）。两者口径**故意不同**——记录是「这次评了什么」，卡片是「这个仓库最近还跑得动吗」。连败计数在出现一次成功或跳过后归零；管理员删掉失败记录时也会按剩下的记录重算

**菜单上的角标数字** = 你名下**未解决**的评审运行数（评出过意见、还没点「已解决」）。角标**不会**因为打开分区而清零 —— 处理完（标记已解决）才减一；同一仓库新 push 产生的新评审会重新计入。全清零后右侧栏吉祥物也不再提醒。

⚠️ 看不到别人的仓库 —— 过滤在服务端完成，改 URL 也拿不到。想让某个仓库出现在这里，找管理员把你的虚拟 Key 加进该仓库的成员名单。

## 评审邮箱门

管理员启用代码评审后，系统需要知道你的**邮箱**（评审结果按 git 提交邮箱**只通知你本人**）。还没填邮箱时进「我的用量」页会弹出一个**必须填写**的对话框：填入邮箱保存后关闭，之后不再出现（随时可在「通知设置」里修改）。这个弹窗**没有关闭按钮、点空白与按 Esc 都关不掉** —— 这是刻意设计：不填邮箱，定向通知就找不到你。

## 消息通知（铃铛）与公告弹屏

页面顶部右侧的**消息通知铃铛**（每个标签页都显示）。管理员发布的站内信分两类：**通知**（只进铃铛）与**公告**（进铃铛 + 打开本页时全屏弹出）；怎么发布、怎么定向见[通知管理](settings.md#通知管理站内信)。

### 铃铛

- **未读角标**：有未读时铃铛显示红色数字（超过 99 显示 `99+`），进页即拉取，之后每 60 秒自动刷新（页面切到后台时暂停，切回立即补一次）。未读数**包含未读的公告**
- **鼠标放上去**：弹出未读消息列表（最近 8 条 + 发布时间），点「查看全部」打开完整列表
- **点击铃铛**：打开「消息通知」弹窗，列出所有发给你（或全员）的通知
  - 未读条目有绿点与「未读」标记、标题高亮；公告条目标题前带「**公告**」小角标
  - **点条目展开正文**（Markdown 渲染），展开即标记该条已读、角标减一；正文是**展开时才从服务器拉取**的（轮询只同步标题与已读状态，长公告不再反复全量下载，展开过一次后本地缓存）
  - 「全部已读」一键把所有未读标为已读
  - 按 `Esc` 或点弹窗外空白关闭
- 定向通知只有被选中的成员能看到；已读状态跟着账号走，换设备登录同一 Key 也是一致的

### 公告弹屏

管理员把类型设为「公告」的消息，你**每次打开（或刷新）「我的用量」页**时，只要还有未读的公告，就会**全屏弹出**——多条未读公告按发布时间**从旧到新**逐条弹出，弹屏右上角显示「第 x / y 条」。

| 操作 | 效果 |
|---|---|
| **我已阅读，不再弹出** | 标记已读，这条公告从此不再弹（仍留在铃铛列表里，可随时翻看） |
| **暂时关闭**（或按 `Esc`） | 只关闭当前这条，**不标已读**——下次进页还会弹 |

- 在铃铛列表里**展开**某条公告、或点「全部已读」，同样算已读，之后也不再弹
- ⚠️ 页面开着的时候管理员**新发布**的公告不会中途弹出来打断你，下次进页才弹
- ⚠️ 公告没有「过期时间」：不点「我已阅读」它会一直弹，这是给停机通知、制度变更这类**需要每个人确认**的消息用的

## 通知设置

左栏「通知设置」分区：配置**你自己**的通知渠道 —— 两类消息会发到这里：你负责的仓库评出问题时的**评审通知**，以及**产出告警的当事人拷贝**（见下）。

| 渠道 | 填什么 |
|---|---|
| 飞书 / 钉钉 / 企业微信 | 各自的机器人 Webhook 地址 |
| Server酱 | SendKey |
| Bark | iOS 装 Bark 后复制的 Device Key |
| 收件邮箱 | 你的邮箱（**需要管理员先配好 SMTP**，否则这一项发不出去；代码评审启用后必填，见上方「评审邮箱门」） |

- 渠道信息**明文回显**：进页面就把已保存的 Webhook / SendKey / 邮箱原样填在输入框里，方便核对；**清空某一项保存 = 清除该渠道**（所见即所得）
- 「发送测试」会拿你**当前填的内容**先保存再各发一条，当场验证渠道通不通
- 「启用我的评审通知」关掉后，任何渠道都不会发给你

### 产出告警的当事人拷贝

当你触发[产出告警](automation.md#产出告警扫描)（空转消耗 / 错误循环 / 编辑失败爆发）时，管理员收到告警的**同一份消息也会发到上面配置的渠道**（含邮件）——你是唯一能立刻停手或修姿势的人，理应第一手知道。

- 没配任何渠道、或关掉「启用我的评审通知」→ 你不会收到，管理员照常收到；两边互不影响
- 一轮持续的空转**只在开头提醒一次**，不会反复轰炸；空转中断（或你开始产出文件）之后再犯才会再提醒

⚠️ 这里的通知与你**能不能触发评审**无关：能不能触发看仓库有没有开「允许在线触发」，能不能收到通知只看这个分区开没开。

## 配置 Agent

左栏「配置 Agent」分区：三个接入指南**合并为一个菜单**，进入后用分区顶部的 Tab 切换 —— **Claude Code / Codex / MCP**，内容见[接入配置](setup-guide.md)：

- **Claude Code**：一键脚本（macOS/Linux 与 Windows PowerShell 两个平台）、手动 `settings.json` 片段、**cc-switch 一键导入**深链；入口地址按你是否在某个方案组内自动计算
- **Codex**：页内分区不跳转，一键脚本 / 手动 `config.toml` + `models.json` / **cc-switch 一键导入**；模型目录来自管理员的方案别名配置
- **MCP**：把 CC Team 的 MCP 端点接进你的 Claude Code / Codex，让 Claude 能查你的配额、看价目表、帮你签到、提交加量申请、翻使用手册。页面按你的虚拟 Key 与访问地址**现算**接入命令，复制执行即可。工具清单与安全说明见 [MCP 接入](mcp.md)

## 申请加量

页面上的「**申请加量**」按钮：选额度池、填理由提交；弹窗内可看自己历史申请的状态与管理员备注。审批在管理员侧（见[用户与配额管理](users.md)）。

## 吉祥物挂件

右下角的吉祥物：

- 10 种角色可选（熊 / 兔 / 猫 / 水獭 / 熊猫 / 小熊猫 / 羊 / 烤面包机等），视线跟随鼠标，点击有表情，浮层里换角色
- **进页问候**：按时段问候 + 一句话的今日用量简报；未签到时提醒签到，签到后道贺
- **评审待办提醒**：名下有未解决的代码评审时，进页后吉祥物优先弹出「你有 N 条代码评审待处理,点我去看」——**点气泡**直达「代码评审」分区；处理完（全部标记已解决）后恢复普通问候
