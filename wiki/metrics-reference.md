# 指标口径参考

本页回答「**这个数字是怎么算出来的**」。适用于管理面板、个人用量页的所有统计。

## 先搞清：两套 Token 口径

| 口径 | 公式 | 用在哪里 |
|---|---|---|
| **报表口径（原始 token）** | input + output + 缓存写 + 缓存读 | 指标卡「今日用量」、趋势图、用户用量表——**图表永远显示真实 token** |
| **配额口径（计权 token）** | (计费输入 + 输出) × 倍率，详见[配额机制](mechanism-quota.md#weighted_tokens-配额货币的完整公式) | 配额扣减、进度条、429 文案 |
| 排行榜「Token 用量」 | input + output（**不含缓存**） | 团队排行榜 |

**报表和配额扣减对不上是设计如此**：倍率、缓存剥离只影响后者。个人用量页「用量分析 → 今日模型请求表」把「实际 Token」和「计入配额」并排展示，就是让你看清这个折算。

## 管理面板指标卡

| 卡片 | 精确算式 | 注意 |
|---|---|---|
| 今日用量 | 当日所有用户的 input+output+缓存写+缓存读 之和 | 缓存计入 |
| 今日请求 | 当日成功拿到用量回执的请求数 | **失败请求不计入**（失败只进错误记录），与「今日错误」正交 |
| 总用量 / 总请求 | 用户表终身累计 | 永不清理，含缓存 |
| 今日错误 | 错误表中今日条目数 | 错误表**只保留最近 200 条且 7 天**——极高频时这是下界 |

「在线」= 最后活跃距今 **1 小时内**。「今日」一律以**北京时间零点**为界。

|---|---|---|

- 半小时桶按**北京时间**取整到 `:00`/`:30`；历史数据里若存在旧版整点键，会自动对半拆进两格（权重各 0.5），不会错位
- 面板数据每 **30 秒**自动拉取一次（开了自动刷新时）

## 产出质量指标公式

原始数据是**工具调用事件**（每次 Edit/Write/Bash 等记一行，含增删行数、成败、命令分类）。时间过滤按北京时间日期。

| 指标 | 公式 | 面板着色 |
|---|---|---|
| 净产出 | Σ新增行 − Σ删除行（只算文件类工具） | 不着色 |
| 文件数 | 触碰过的不同文件数 | — |
| 失败率 | 文件类失败次数 ÷ 文件类总次数 | <10% 绿，≥30% 橙 |
| 重写率 | 删除行 ÷ 新增行 | <30% 绿，≥80% 橙 |
| 验证密度 | 验证类调用次数 ÷ 文件类调用次数 | 0 橙，0.1–0.8 绿 |
| Token 效率 | 区间输出 token ÷ 净产出（净产出 ≤0 时为空） | 不着色 |

**验证类 = 命令分类为 test 或 lint**：`pytest / vitest / jest / mocha / playwright / go test / cargo test`、`eslint / biome / prettier / flake8 / ruff / stylelint` 等。命令分类还有 build（make/webpack/vite build/tsc/npm run build…）与 git 两类。

**行数记法**：Edit 按新旧串行数；MultiEdit 累加各段；Write 全量按新增；Codex 的 `*** Begin Patch` 按补丁 +/- 行拆分多文件。

**项目分布归并**：以会话为单位归项目——按路径带权找主导子树（根级最重子目录 ≥60% 则单一项目；≥20% 的多个子目录各成簇）；会话跨多项目时**整段记给权重最大的主项目**，跨项目文件数如实单列。榜单取新增行 Top 50。「零产出成员」= 区间内有输出 token 但无任何工具事件的成员。

## 产出告警的精确阈值

默认值如下（可在 config 覆盖），每 60 秒扫描一次：

| 告警 | 触发条件（全部满足） | 冷却 |
|---|---|---|
| 空转消耗 | 当前北京小时内输出 token ≥ **100,000** 且最近 **60 分钟**无任何文件类事件 | 30 分钟 |
| 错误循环 | 最近 **10 分钟**内同一用户同一类错误 ≥ **5** 次（剔除兜底类 `tool_error`）**且**窗口内没有成功的文件编辑（有进展不上报） | 60 分钟 |
| 编辑失败爆发 | 最近 **30 分钟**内文件类事件 ≥ **10** 次 **且** 失败占比 **> 50%**（严格大于） | 30 分钟 |

推送格式：【产出告警】类型 · 用户名 + 详情 + 北京时间；推送侧另有每条 60 秒冷却。产出数据（工具事件/告警）保留 **90 天**。

## 等值成本计算

参考牌价单位 **USD / 1M tokens**，默认（Claude 官方价，可在设置页改）：

| 模型 | 输入 | 输出 | 缓存写 | 缓存读 |
|---|---|---|---|---|
| claude-opus | 15 | 75 | 18.75 | 1.5 |
| claude-sonnet | 3 | 15 | 3.75 | 0.3 |
| claude-haiku | 1 | 5 | 1.25 | 0.1 |

- 模型匹配顺序：精确名 → **最长前缀匹配** → `*` 兜底；都查不到的模型计 0 并列入「未定价」清单提示补价
- **峰谷分时价复用各方案自己的高峰时段**（不是全局一套）；未配高峰的方案全天基础价；峰价留空回落基础价，**显式填 0 = 峰时段免费**
- 缓存读价未填时按 **缓存写价 ÷ 12.5** 推算（Claude 牌价比例）
- 配了峰谷走小时级数据分档计价，历史缺口按基础价回填，保证日总量守恒
- **价格是查询时现算的：改牌价后全部历史立即按新价重算**——这是参考值工具，不是账单存档

## 团队排行榜

7 个维度（时间窗：今日 / 本周一起 / 本月 1 日起，均北京时间）：

| 维度 | 排序 | 取值 |
|---|---|---|
| 缓存率 | 高→低 | 缓存读 ÷ (缓存读 + 协议修正后新增输入) |
| 代码质量 | 高→低 | 综合分，见下 |
| 代码行数 | 高→低 | 净产出 |
| Token 用量 | 高→低 | input + output（不含缓存、不计倍率） |
| 效率比 | **低→高** | token/行 |
| 上下文健康度 | **低→高** | 每次请求的新增输入 token |
| 活跃度 | 高→低 | 请求数 |

**代码质量分**：失败率(权重 0.5) + 验证密度(0.3) + 重写率(0.2)，窗口内 min-max 归一后加权 100 分制。**参与资格：窗口内有文件编辑**；少于 2 人有编辑时全员不评分（不给假 50 分）。

并列时按请求数降序兜底；无数据一律排末尾。

## 会话统计

- **会话识别**：请求头 session-id → 请求体 prompt_cache_key → 首轮消息摘要 → 都没有则**不落会话表**（接口披露未归属量）
- **可读标题**：Claude Code 读本地会话文件的 AI 标题（**最后一条**，随对话演化）；Codex 取首条真实用户消息（跳过注入前缀、截 48 字）；读不到回退显示会话标识前 18 字符。标题不落库、每次现读
- **缓存率** = 缓存读 ÷ (缓存读 + 新增输入)，其中 Responses 协议的新增输入要先减去折叠在 input 里的缓存命中（否则命中率被压到 50% 上限）；分母为 0 显示「无数据」而非 0%
- **分档**（取三项最差）：缓存率 ≥90% 优 / ≥80% 良；失败率 <10% 优 / <30% 良；单轮新增输入 ≤3000 优 / ≤8000 良
- 会话数据保留 **90 天**；请求 ≤2 的会话标记为「碎片」

## 使用日历热力图

- 窗口 = 今天往回 **371 天**（含今天），按北京时间
- **分位数着色**（相对自己，不是固定阈值）：活跃天（有流量）的 25/50/75 分位切成 5 档色阶——所以「深色」= 超过你过去一年 75% 的活跃天
- 摘要：活跃天数 = 有流量的天数；最长连续遍历**有记录的日期序列**（无流量日不在序列里、不会打断计数，注意这与直觉不同）；最高单日 = 总 token 最大的那天

## 数据保留期总表

| 数据 | 保留 | 说明 |
|---|---|---|
| 日汇总主表（用量/请求/缓存） | **永久** | 所有报表的基石 |
| 模型/客户端日表、两张小时表 | 400 天 | 400 天是刻意下限：保证「按年」窗口在 12 月底也查得到年初数据 |
| 按用户的当日小时数据 | 7 天 | 粒度最细、只服务短期排查 |
| 错误记录 | 7 天 且 ≤200 条 | 双重清理 |
| 会话表、产出工具事件、产出告警 | 90 天 | 两表同期限（项目分布跨表关联，不同期会留孤儿） |
| 审计日志 | 最近 3000 条 | 「清空全部数据」也不删审计 |
| 配额调整历史 | 最近 100 条 | 含 AUTO 与手工 |
| 临时加量/签到当日操作 | 7 天 | 本身按日失效，清理只为回收空间 |
| 请求日志文件（logs/） | 30 天 | 不记对话内容 |
| 图片识别缓存 | 最新 5000 条 | 按条数 |
| 粘性会话绑定 | 内存，重启丢失 | 上限 1000 条 |

清理是**惰性**的：每天第一次请求触发一次，事务内一次跑完，没有定时任务。
