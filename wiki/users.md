# 用户与配额管理

入口：设置页底部「**用户管理**」按钮。

## 虚拟 Key（用户）

用户管理弹窗分两层：**全局用户** + **每方案分配**。

### 全局用户

- **虚拟 Key**：形如 `jx-xxxx` 的成员凭证，创建后发给成员
- **名称**：成员在报表里显示的名字
- **失效时间**：到期的 Key 自动失效（适合临时外部协作者）
- **禁用**：一键停用，请求立即被拒

### 每方案分配

在具体方案下给用户分配：

- **真实 Key**：该成员在这个方案上游使用的凭证（如上游服务的 API Key），用于上游侧的用量归属；未分配真实 Key 的用户不计入方案卡片的用户数
- **个人配额**：该成员在此方案的每日额度
- **禁用**：单独禁用某成员对某方案的使用

配额模型：**配额存在额度池上**——个人与池级限额、临时加量都按池生效（详见[配额与计费机制](mechanism-quota.md#额度池配额的唯一载体)）。限额 ≤0（个人与池都没设）= 不限制。

## 临时额度：三个操作到底改了什么

用户管理里的「**临时额度**」按钮，三个动作的精确语义（都写在「当日操作」里，键为池 + 用户 + 北京日期，**次日日期一变自动失效**）：

| 动作 | 精确语义 |
|---|---|
| 临时加量 | **设置/覆盖**当日加量值（不是累加！已加 1 万再加 5 千 = 变成 5 千）。生效后限额 = 基础限额 + 加量值。作用于**整个池**（同池其他方案一起生效） |
| 重置今日用量 | 记录当日已用计权量为**基线**，此后按「当日用量 − 基线」判定，配额回满。统计行不删，报表照常显示真实用量 |
| 撤销今日手工操作 | 删除当日该用户的全部手工痕迹（加量与基线一起清），回到系统自然状态 |

> ⚠️ **累加的例外**：签到奖励和加量申请发放是**累加**到当日加量上的，与手工加量共存。

成员侧会在「我的用量」页的配额提示条里看到临时加量标记。

## 签到与奖励

- 开关与参数在设置页「全局配置」的「签到与加量申请」区：默认奖励区间 **[10,000, 100,000]** token，随机数在闭区间内均匀抽取
- 成员每日在「我的用量」页签到，随机获得一笔 token 额度；**随机数只抽一次，用户可访问的每个额度池各加同一份**（不是每池独立抽）
- 连续天数（streak）纯展示、无奖励加成；未签时显示「今天还能保住的连续」
- 签到是**成员自助**的，替代一部分手工加量的沟通成本

## 加量申请（审批流）

1. 成员在「我的用量」页点「申请加量」，选**额度池**、填写理由（必填，≤200 字）提交；**提交不占每周次数**——只有管理员处理过的申请才计数
2. 规则：每北京日限提交 1 次（固定）；每周处理上限默认 **3**（可配 0–1000），周窗口 = 本周一 00:00（北京时间）；池不限量时拒绝申请
3. 管理员在设置页侧栏「**加量申请**」（有待处理时显示角标）里查看申请历史，通过 / 拒绝并可附备注（≤200 字）；提交时会即时推送到已配置的通知渠道
4. 「发放加量」= 给指定池发当日临时加量（**累加**式）并自动标记已处理；结果回写申请历史，成员侧可见

## 操作日志

设置页侧栏「操作日志」记录 admin / system / checkin / request 四类日志（含管理员改动、自动配额调整、签到、申请），保留最近 3000 条，出问题回溯用。
