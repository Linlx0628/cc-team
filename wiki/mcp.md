# MCP 接入（让 Claude 用上 CC Team）

CC Team 内置 MCP（Model Context Protocol）端点。接入后，你的 Claude Code / Codex 会话里会多出 6 个工具——Claude 可以**自己查配额、看价目表、帮你签到、提交加量申请**，还能随时翻阅本使用手册；如果你负责某几个仓库（名字在它们的成员名单里），还会多出 3 个评审工具（见下）。

## 一条命令接入

> 入口：「我的用量」页 → 侧栏「**配置 MCP**」分区——页面会按你的虚拟 Key 与当前访问地址**自动生成**下面的命令，直接复制即可，无需手改。

```bash
claude mcp add cc-team --transport http https://你的服务器地址:6789/mcp --header "Authorization: Bearer jx-你的虚拟Key"
```

- 服务器地址与端口就是你的 CC Team 网关地址
- 虚拟 Key 即你的身份（与管理面板「用户管理」发的 `jx-xxxx` 相同）
- Codex 同样支持 MCP：在 Codex 配置里加一个 HTTP MCP server，URL 与 header 相同

接入后重启客户端会话即可。可用 `claude mcp list` 确认连接状态。

## 工具一览

| 工具 | 作用 |
|---|---|
| `my_quota` | 查我的配额：各池余额（已用/上限/剩余/当前峰谷倍率/临时加量）、今日合计、签到状态、本周加量申请余额 |
| `price_list` | 当前时段的模型倍率价目表（rate 越低越便宜） |
| `check_in` | 每日签到，随机领 token 奖励（每天一次） |
| `request_quota` | 向管理员提交加量申请（每天限 1 次，每周被处理数有上限） |
| `my_usage` | 查用量明细：今日或指定日期范围、按模型、24 小时分布、按客户端 |
| `leaderboard` | 团队排行榜（7 个维度 × 今日/周/月） |

典型玩法：

- 开始大任务前让 Claude「查下我的配额还剩多少」；撞 429 后 Claude 自己解释原因（限流/配额/上游限额）并决定要不要等或申请加量
- 「看看哪个模型便宜」→ Claude 读价目表帮你挑，再切模型
- 「帮我签到」→ Claude 调用签到工具（连续天数不会断）

## 代码评审工具（需管理员授权）

管理员把你加进某个仓库的**成员名单**（设置页 → 代码评审 → 该仓库「编辑」→ 负责这个仓库的成员）之后，工具列表里会**多出三个**：

| 工具 | 参数 | 作用 |
|---|---|---|
| `code_review_list` | `limit`（最近多少次运行，默认 10，最多 50） | 查看**你名下的**仓库、各自上次评审状态/上次提交/连续失败次数，以及它们的运行记录（状态、触发方式、范围、意见数、token）。看不到别人负责的仓库 |
| `code_review_trigger` | `repo`（仓库名或 8 位 id；缺省 = 你名下可触发的仓库） | 触发一次评审。**写操作**：会真的消耗 token，并在管理面板留下记录 |
| `code_review_findings` | `repo`（可选，缺省 = 你名下全部）、`since`（如 `7d`/`24h`/`2026-09-18`）、`limit`（默认 20）、`unseenOnly`（只看没看过的） | **查询评审发现的具体问题**：文件、行号、问题描述、建议改法。这才是「最近有什么代码问题」该用的工具 |

- ⚠️ **不是任何仓库成员的 Key 看不到这两个工具**——不是调用报错，而是工具列表里根本没有（管理员也是靠这一步确认授权是否生效）
- 想在自己的「我的用量」页看评审结果？被加进仓库成员名单后，那里会多出一个「代码评审」分区，只显示你负责的仓库
- **典型用法**：在 Claude Code 里直接问「最近有没有代码评审的问题？」—— 它会调 `code_review_findings`，把**具体是哪几处、什么问题、建议怎么改**读给你听；你决定改哪条之后，还能让它帮你改
- `code_review_list` 与 `code_review_findings` 的区别：前者是**概览**（哪些仓库、上次评了没有、几条意见），后者是**明细**（具体问题 + 建议）。问「有什么问题」用后者
- ⚠️ 只能看**自己负责的仓库**；点名别人的仓库会直接报错，不会返回别人的代码问题
- 限频：**每个 Key 60 秒只能触发一次**，超了工具会返回「触发过于频繁，请 Ns 后重试」
- 评的是仓库里**已提交**的最新代码，不是本地未提交的改动——想评什么先 commit / push
- 还有一条 REST 等价接口 `POST /api/code-review/trigger`（同一个 Key、同一套授权与限频），适合放进 CI，见[代码评审](code-review.md)

## 使用手册资源

端点同时把本手册（`wiki/` 下的页面）暴露为 **MCP resources**——Claude 可以直接查阅「配额怎么算」「429 是什么意思」等文档来回答你的问题，无需你打开浏览器。手册更新后资源即时同步（读盘直取）。

## 安全提示

- `Authorization` 里的虚拟 Key 就是**你的身份**：通过它能看到你的用量、以你的名义签到和申请加量。不要把带 Key 的命令发到群里或提交进代码仓库
- 管理端没有开放 MCP——所有工具都是成员级别的，查不到别人的明细（排行榜只有脱敏的排名值）
- 请求是**无状态**的：每个请求独立携带 Key，服务端不存会话
